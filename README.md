# ПОС — Преподавательская Оценка Студентов

Консольный модуль учёта оценок: студенты, рубрикатор критериев, оценки, итог по весам и экспорт.
DDD + Clean Architecture + паттерны GoF. .NET 10.

## Запуск

Установите SDK .NET 10 и выполняйте команды из каталога с `Pos.sln`.

```bash
dotnet run --project Pos.ConsoleApp            # интерактивное меню
dotnet run --project Pos.ConsoleApp -- --demo  # сквозной сценарий из ТЗ
dotnet test                                    # юнит-тесты
```

Демо-сценарий: критерии и студенты → оценки → попытки нарушить правила → исправление → итог по двум правилам → экспорт в `final-grades.csv`.

Студенты, критерии и оценки хранятся в памяти до завершения программы. CSV содержит выгрузку итогов.

## Ubiquitous Language

| Термин ТЗ | В коде | Что это |
|---|---|---|
| студент | `Student` | кого оценивают |
| рубрикатор | `Rubric` | набор критериев курса |
| критерий | `Criterion` (`MaxScore`, `Weight`) | за что ставят балл; максимум и вклад в итог |
| балл | `Score` | неотрицательное число, верхнюю границу задаёт критерий |
| оценка | `Evaluation` | «этому студенту по этому критерию поставили такой балл» + дата, комментарий |
| итог | `FinalGrade`, `GradeCalculator` | результат из оценок и рубрикатора, шкала 0–10 |
| правило итога | `IGradingStrategy` | как именно оценки превращаются в итог |

## Карта DDD

**Агрегаты** объединяют объекты, изменения которых подчиняются общим правилам.

- `Rubric` — корень агрегата критериев. Метод `AddCriterion` проверяет уникальность названия без учёта регистра.
- `Student` — отдельный агрегат, живёт независимо от оценок.
- `Evaluation` — отдельный агрегат, ссылается на студента и критерий по идентификаторам. Исправление оценки меняет состояние самой оценки.

**Entity и Value Object.** После исправления балла сущность `Evaluation` сохраняет свой `EvaluationId`. Два объекта `Score` со значением 7 равны по значению. Другие объекты-значения — `MaxScore`, `Weight`, `StudentId`, `CriterionId` и `EvaluationId`. `FinalGrade` и `CriterionResult` представляют итог расчёта и его разбивку по критериям.

**Инварианты и кто их охраняет:**

| Правило | Где |
|---|---|
| балл не выходит за пределы критерия | `Score` (≥ 0), `Criterion.EnsureAllows` (≤ max); вызывается в `EvaluationFactory` и `Evaluation.Correct` |
| оценку можно выставить только по критерию из рубрикатора | `Rubric.GetCriterion` в `EvaluationFactory` |
| итог согласован с текущим набором оценок | `GradeCalculator`: итог не хранится, считается заново; чужие оценки и оценки вне рубрикатора отклоняются |
| max и вес > 0, имена не пустые | конструкторы `MaxScore`, `Weight`, `Student`, `Criterion` |
| одна оценка на пару «студент–критерий» | `GradingFacade.GiveEvaluation` (правило на стыке агрегатов) + проверка в `GradeCalculator` |
| нельзя удалить критерий, по которому есть оценки | `GradingFacade.RemoveCriterion` |

**Идентификаторы.** Следующий номер равен максимальному среди текущих записей плюс один. Номера студентов и оценок выдают репозитории через `NextId()`, номера критериев выдаёт рубрикатор. После удаления записи с максимальным номером этот номер может использоваться повторно.

**Repository (порты):** `IStudentRepository`, `IRubricRepository`, `IEvaluationRepository` в слое UseCases; реализации — в Infrastructure.

**Domain Service:** `GradeCalculator` — итог зависит одновременно от рубрикатора и от оценок, ни одной сущности он не принадлежит.

### Формула итога

`итог = Σ (балл / max × вес) / Σ вес × 10`. Вес относительный, веса не обязаны давать в сумме 1.
Невыставленная оценка зависит от правила: `strict` считает её нулём, `progress` исключает критерий из расчёта.

## Архитектура: Clean Architecture

Прямые ссылки между проектами приложения:

```
Pos.ConsoleApp ──► Pos.Infrastructure ──► Pos.UseCases ──► Pos.Entities
       └─────────────────────────────────► Pos.UseCases
```

Меню и демо вызывают сценарии через `IGradingFacade` из `Pos.UseCases`. Ссылка на `Pos.Infrastructure` нужна точке сборки приложения для регистрации репозиториев и экспортёра. Интерфейсы этих компонентов объявлены в `Pos.UseCases`, а реализации находятся в `Pos.Infrastructure`. `Pos.Entities` — внутренний слой с доменными правилами без ссылок на другие проекты.

| Слой | Проект | Содержимое |
|---|---|---|
| Entities | `Pos.Entities` | сущности, VO, `EvaluationFactory`, `GradeCalculator`, стратегии итога |
| Use Cases | `Pos.UseCases` | `IGradingFacade`/`GradingFacade`, порты репозиториев и экспорта, DTO |
| Infrastructure | `Pos.Infrastructure` | in-memory репозитории, `CsvFinalGradeExporter` |
| Presentation | `Pos.ConsoleApp` | меню, ввод, демо-сценарий, `CompositionRoot` |

**DI.** `CompositionRoot` вызывает `AddUseCases()` и `AddInfrastructure()` и создаёт контейнер `Microsoft.Extensions.DependencyInjection`. Контейнер передаёт реализации портов в конструктор фасада при запуске приложения.

## Паттерны GoF

| Группа | Паттерн | Где | Какую боль закрывает |
|---|---|---|---|
| Порождающий | Factory | `EvaluationFactory` | находит критерий в рубрикаторе и проверяет диапазон балла до создания оценки |
| Структурный | Facade | `GradingFacade` | предоставляет меню единый интерфейс сценариев и координирует вызовы домена, репозиториев и экспортёра |
| Поведенческий | Strategy | `IGradingStrategy` + `StrictWeightedStrategy`, `ProgressWeightedStrategy` | позволяет выбирать правило обработки пропущенных оценок при расчёте итога |

## Тесты

`Pos.Tests` (xUnit): инварианты фабрики и исправления оценки, рубрикатор и VO, расчёт итога обеими стратегиями.
